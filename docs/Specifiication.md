  ## 1. Working title & one-liner

  | Option | Notes |
  | --- | --- |
  | **FLATBRIZ** | Official product name |

  **One-liner (draft):**  
  **FLATBRIZ** is a digital platform for residential societies to manage residents, flats, visitors, bills, complaints, and community life — from one mobile app and one admin dashboard.

  ---

  ## 2. Purpose / why it exists

  Many societies still run day-to-day work on WhatsApp groups, Excel sheets, and paper registers. That creates confusion for residents, extra work for society admins, and weak control at the gate.

  **FLATBRIZ** brings residents, building admins, and security guards onto one shared system so everyday society operations are clearer, faster, and easier to track.

  ---

  ## 3. Positioning

  - **Brand:** FLATBRIZ
  - **Category:** Society / building management platform (multi-society SaaS)
  - **What it is:** Mobile app for residents & guards + web console for building admins & platform operators
  - **What makes it different (draft):**
    - One phone can belong to multiple societies / roles
    - Building-code based onboarding with admin approval
    - Separate experiences for resident, guard, building admin, and super admin
    - Modules can be enabled per society

  ---

  ## 5. Core value propositions (draft)

  1. **Run the society digitally** — flats, residents, visitors, bills, and complaints in one place  
  2. **Residents get self-serve access** — check dues, raise issues, join votes, see announcements  
  3. **Gate operations stay organised** — guards log visitors against flats  
  4. **Admins stay in control** — approve join requests, manage wings/flats, oversee operations  
  5. **Works across many societies** — one platform, many buildings, roles per membership

  ## 7. Key user journeys (short stories)

  1. **Join a society** — Resident enters Building Code → verifies phone/email OTP → requests a flat → admin approves → access unlocked.  
  2. **Pay / view maintenance** — Resident opens Bills → sees dues by flat → pays (mock today; real gateway later).  
  3. **Log a visitor** — Guard records visitor against a flat → entry/exit tracked → admin can review the log.  
  4. **Raise a complaint** — Resident submits issue → admin tracks status → resident sees updates.  
  5. **Society communication** — Admin posts announcement / creates vote → residents see it on mobile and respond.
